# Frontend

TypeScript, React, ViteによるWeb UIを配置する.
GoバックエンドのREST APIから記事, ニュースソース, タグを取得する.
ボタンは共通の`Icon`コンポーネントを使ったアイコン表示に統一し, 操作名は`aria-label`と`title`で提供する. 選択肢名など常時表示が必要な文字はボタン外へ配置する.

## 起動方法

```bash
npm install
npm run dev
```

先にバックエンドを`http://localhost:8080`で起動する.
ブラウザでViteが表示したURLを開く.
開発中の`/api`へのアクセスはViteがバックエンドへ中継する.
待受アドレスは`FRONTEND_HOST`, ポートは`FRONTEND_PORT`, 許可するホスト名は`FRONTEND_ALLOWED_HOSTS`, APIの中継先は`BACKEND_PROXY_URL`で変更できる.

VPSではViteを`127.0.0.1:5173`でHTTP待受し, Tailscale Serveがtailnet内のHTTPS通信を中継する.
`FRONTEND_ALLOWED_HOSTS`にはTailscale管理画面に表示される`*.ts.net`の完全修飾ドメイン名を指定する.
設定と配置方法はルートの`README.md`を参照する.

別のAPI URLへ接続する場合は`VITE_API_BASE_URL`を指定する.

```bash
VITE_API_BASE_URL=https://api.example.com/api/v1 npm run dev
```

## 操作

- カードを左へフリック: スキップして既読にする
- カードを右へフリック: あとで読むに保存
- カード左上のゴミ箱ボタン: 削除記事一覧へ移動
- カード右上の星ボタン: お気に入りを切り替える
- 左右の矢印キー: フリックと同じ操作
- 記事タイトルのタップまたはEnterキー: 元の記事を新しいタブで開き, 既読に変更
- 「続きを読む」: カード内の全文表示へ切り替える
- 集中モード: 絞り込みと周辺操作を隠し, カードの選別へ集中する

通常の記事列には, 未読かつ「あとで見る」と削除記事一覧に入っていない記事だけを表示する.
状態はREST APIを通じてバックエンドへ保存する.
バックエンドをDocker Composeで起動した場合, 状態はPostgreSQLへ保存する.
「スキップした記事を戻す」ではスキップ由来の既読だけを解除し, 保存記事と削除記事には影響させない.
削除記事は削除記事一覧から個別に戻す.

通常の記事列は最初に20件だけを取得し, 残り5件になると次の20件を先読みする.
お気に入り, あとで見る, ゴミ箱はページを開いた時に50件ずつ取得し, 必要に応じて続きを読み込む.

各一覧は独立したページとして表示し, ハッシュURLで切り替える.

- お気に入り: `#/favorites`
- あとで見る: `#/saved`
- 削除記事: `#/deleted`
- タグ管理: `#/tags`
- ニュースソース管理: `#/sources`

タグ管理ページでは, タグの追加, 名前変更, 削除ができる.
1つのRSS・Atomニュースソースに複数のタグを割り当てられ, 割り当て操作はニュースソース管理ページまたは記事カードで行う.
記事カードのタグ選択画面ではタグ名の検索と新規作成ができ, 利用頻度が高く最近使われたタグから表示する.
タグを削除してもニュースソースと記事は削除せず, 削除したタグの割り当てだけを解除する.
タグと割り当てはREST APIへ保存する.
ニュースソース管理ページでは, RSS・Atomソースの追加, 取得の有効・停止, タグの割り当て, 削除ができる.
ドラッグ操作でニュースソースの優先順位を変更でき, 並び順はバックエンドへ保存する.
並び替えだけでは重複判定を変更せず, ヘッダーの更新アイコンで有効な全ソースを再取得した時に新しい優先順位を反映する.
異なるニュースソースに同じ記事URLが存在する場合は, 一覧で上にあるソースの記事を優先する.
RSS・Atomの形式はユーザーが指定せず, フィードの取得内容から自動判定する.
各ソースには選択済みタグだけを表示し, プラスボタンからタグ一覧を開いて複数選択する.
ソースの追加時はバックエンドが実際のフィードを取得し, RSS 2.0またはAtom 1.0を自動判定する.
OPMLファイルを選択してソースを一括追加でき, フォルダー階層はタグとして取り込む.
取込後は追加, 重複, 失敗, 新規タグの件数を表示する.
登録中のソースと複数タグは`OPML出力`からファイルとして保存できる.

通常のカードには高さに収まる要約と本文を表示する.
文章がカードの高さを超える場合は「続きを読む」を表示し, 全文表示内の縦スクロールで提供された要約と本文を読む.
通常カードでは縦方向のスクロールと横方向のフリックを判別して処理する.

異なるニュースソース間で正規化したURLが一致する記事は, 最も優先順位が高いソースの記事だけを表示する.
代表記事には非表示にした重複記事の件数を表示しない.
優先順位を変更してヘッダーの更新アイコンを押すと代表記事が切り替わり, 記事の閲覧状態は新しい代表記事へ引き継ぐ.

記事カード左側では, 「ニュースソース」または「タグ」のどちらか一方を選んで記事を絞り込める.
ニュースソースとタグの条件は同時適用しない.
モバイルでは同じ選択欄を記事カード上部へ表示する.

ヘッダーのハンバーガーメニューから, ソース, タグ, お気に入り, あとで見る, ゴミ箱へ移動できる.
